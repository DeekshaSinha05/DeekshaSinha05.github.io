AI SYSTEMS · PUBLIC PROTOTYPE

Hirely.AI

From résumés to structured screening information.

A local-LLM recruiting prototype with PDF parsing, structured model responses, and interview-slot suggestions. Part of the broader Hirely.AI project.

≈70%project-reported reduction in screening time
Explore repository ↗
Engineering brief +

Problem

Turn PDF résumés and a job description into structured screening information and suggested interview slots.

Public implementation

The Python prototype parses PDFs with PyMuPDF, calls a locally hosted Llama model through Ollama, and processes structured scores, reasoning, and suggested tool actions. Scheduling uses mocked slots.

Design choice

Local inference gives control over where model execution runs, while requiring a locally provisioned model. This is a prototype workflow, not evidence of a production deployment.

Outcome & scope

The résumé reports approximately 70% less screening time for the broader project. The public repository does not document that measurement; embeddings are listed there as a future extension.

Public implementation reference: project repository.

DISTRIBUTED SYSTEMS · ENGINEERING PROJECT

Skier Tracking System

High throughput. Decoupled processing.

A distributed backend with asynchronous messaging, rate limiting, and back-pressure to keep ingestion and processing loosely coupled.

200K+requests per day
Engineering project
Engineering brief +

Problem

Support a stream of skier activity requests while separating request handling from downstream processing.

Implementation

Built a Spring Boot backend with EC2, RabbitMQ, and DynamoDB. Asynchronous messaging, rate limiting, and back-pressure are the core engineering techniques described in the project.

Outcome

Reported processing volume: 200K+ requests per day. Daily volume describes the workload; it is not a peak-throughput or latency benchmark.
